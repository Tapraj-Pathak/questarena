You are a senior product engineer, full-stack architect, game developer, Web3 engineer, smart-contract developer, and UI/UX designer.

Build **QuestArena from scratch** as a fully functional, playable, professional Web3 gaming competition platform.

Do not create a landing-page-only project, a static dashboard, a Figma-like mockup, or a collection of non-functional screens.

The user must be able to open the application, sign up, log in, browse competitions, play games, join competitions, see live results, and experience the complete competition lifecycle.

Sponsors must be able to create campaigns, fund competitions, promote games or brands, and monitor engagement.

Build the actual application, not merely a visual representation of it.

Do not stop after planning. Create the project, implement it, run it, and test it.

# 1. PRODUCT IDENTITY

Product name: QuestArena

Tagline: Play. Compete. Prove. Earn.

Product description:

QuestArena is a sponsored gaming competition platform connecting players, game developers, and brands.

It has two primary competition categories:

### CATEGORY A — GAME-SPONSORED COMPETITIONS

Existing game developers and studios sponsor their own games to promote them.

Examples:
- A chess game developer sponsors a chess tournament.
- An indie game studio sponsors a challenge to attract new players.
- A multiplayer game developer launches a seasonal competition.
- A game publisher promotes a new game through QuestArena competitions.

The game developer is the sponsor.

The campaign promotes the developer's game and attracts players to it.

Where supported, provide a playable integration, game launch link, embedded game, or external game adapter.

Do not pretend that an external game is playable unless an actual integration exists.

### CATEGORY B — BRAND-SPONSORED BUILT-IN GAMES

QuestArena provides its own built-in games.

External brands sponsor competitions hosted on those games.

Examples:
- A technology company sponsors a Neon Reaction tournament.
- A gaming accessories brand sponsors a memory challenge.
- A software company sponsors a daily puzzle competition.

Brands can receive:
- Sponsored campaign placement.
- Logo and brand visibility.
- Campaign banners.
- Sponsor profile placement.
- Sponsored game pages.
- Competition announcements.
- Measurable engagement analytics.

Sponsor funding pays for the competition rewards.

Do not confuse advertising revenue with the actual prize pool. Track campaign fees, promotional services, and prize funding separately.

### CORE BUSINESS MODEL

Potential revenue sources:
- Game promotion campaign fees.
- Brand sponsorship campaign fees.
- Premium promotional placements.
- Advanced campaign analytics.
- Future revenue-sharing agreements with game developers.

Do not implement arbitrary fees that have no corresponding product functionality.

# 10. BUILT-IN GAMES — MUST BE PLAYABLE

Implement at least two complete built-in games.

These games must work now, not be placeholder screens.

### GAME 1 — NEON REACTION

Use Phaser 3 and TypeScript.

Gameplay:

1. Player starts a session.
2. A countdown begins.
3. Targets appear in randomized positions.
4. Player reacts by clicking or tapping.
5. Correct reactions increase the score.
6. Incorrect reactions apply a penalty.
7. Each round has a controlled duration.
8. The game ends after the configured rounds.
9. Results are submitted to the backend.
10. The player sees a detailed results screen.

Include:
- Start screen.
- Countdown.
- Gameplay.
- Score display.
- Reaction timing.
- Round progress.
- Game-over screen.
- Replay option.
- Result submission.
- Competition leaderboard integration.

Generate a server-controlled session configuration and random seed.

Do not accept arbitrary client-submitted scores as authoritative.

### GAME 2 — MEMORY MATCH

Implement a fully playable memory-matching game.

Gameplay:

1. Cards are shuffled.
2. Player flips two cards.
3. Matching pairs remain revealed.
4. Non-matching cards turn back.
5. Track elapsed time and moves.
6. Game ends when all pairs are matched.
7. Calculate the result.
8. Submit evidence to the backend.

Include:
- Multiple difficulty levels.
- Game timer.
- Move counter.
- Score calculation.
- Replay.
- Results page.
- Competition leaderboard integration.

Use deterministic, server-configured game parameters where practical.

### GAME ARCHITECTURE

Create a common game adapter interface.

The platform should support new games without rewriting the competition engine.

Separate:
- Game initialization.
- Session configuration.
- Gameplay.
- Evidence generation.
- Result submission.
- Result validation.
